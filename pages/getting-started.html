LEO DOCS/FIRST SETUP
START WITH THE FILES YOU HAVE

Three files.
One tidy router.

Put the router, route map, and loader beside your existing HTML. LEO does not ask you to reorganize your site or install a framework.

01

Keep your pages as HTML

Use full, normal HTML documents. In the shell page, add one element where routed page content should appear. Keep your shared header and navigation outside it.

index.htmlHTML
<header>Your site navigation stays here</header>
<main id="pidRoot"></main>
<div id="pidLoader" hidden></div>
02

Describe paths in data.json

Each route points to a regular HTML file. The included pig-loader.html is enabled by default; change the file name or set "loader": false to disable it.

data.jsonJSON
{
  "mode": "spa",
  "loader": "pig-loader.html",
  "defaultRoute": "/",
  "routes": {
    "/": { "file": "pages/home.html" },
    "/contact": { "file": "pages/contact.html" }
  }
}
03

Mark only the links you want LEO to handle

Point leo-pid at a path from your route map. Unmarked links remain regular browser links.

navigation.htmlHTML
<a href="/contact" leo-pid="/contact">Contact</a>

<!-- Use a normal link for files or external sites. -->
<a href="/brochure.pdf">Download brochure</a>
SERVER NOTE

For clean URLs such as /contact to work after a reload, configure your static host to serve the router’s index.html for unknown paths. This project’s preview already does that.
