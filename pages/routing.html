LEO DOCS/ROUTES & TRANSITIONS
URL IN, PAGE OUT

A route is just
a path and a file.

LEO reads the current URL, finds its entry in data.json, and replaces only the contents of #pidRoot. Your header, styles, and router stay mounted.

01

Every transition clears the old page

The previous page’s root children are removed before the new document’s body is mounted. Page-specific stylesheets are swapped too; site-wide stylesheets and scripts live in your outer shell.

data.jsonJSON
{
  "routes": {
    "/": { "file": "pages/home.html" },
    "/contact": {
      "file": "pages/contact.html",
      "scripts": ["pages/contact.js"]
    }
  }
}
02

Browser history still works

LEO updates the address bar with the History API. Back, forward, reload, query strings, and URL fragments continue to work. A direct visit to /contact resolves to the same mapped HTML page.

03

Pick SPA or full-page mode

Use "mode": "spa" for client-side page swaps. Use "mode": "multi-page" (or "spa": false) to let marked links perform a normal full-page navigation while keeping the same JSON route map for direct URLs. Your host must serve the shell at each clean path.

data.jsonJSON
{
  "mode": "multi-page",
  "defaultRoute": "/",
  "routes": {
    "/": { "file": "pages/home.html" },
    "/contact": { "file": "pages/contact.html" }
  }
}
04

Match path parameters and load JSON

Use :slug for a dynamic segment and add a data path to fetch matching JSON. Bind values into ordinary HTML with data-leo-text, or read them from LEO.currentRoute and component modules.

data.jsonJSON
"/posts/:slug": {
  "file": "pages/post.html",
  "data": "data/posts/:slug.json"
}

JAVASCRIPT

Use LEO.go("/contact") or listen for leo:routechange. Component modules export mount(context) and return a cleanup function or an object with update and unmount. Each component's linked CSS stays inside its Shadow DOM.
